# pstack principles and foundational skills: reviewed on-demand access

This is the exact 38-skill slice in [issue #93](https://github.com/yersonargotev/packy-catalog/issues/93):
24 principles and 14 foundational/utility skills, on Codex and Claude Code.
pstack advances from 4.5.0 to 4.6.0 as a Catalog contract migration. Its upstream
remains `cursor/plugins@0148b78c56c72a1b8412055913c79f767095b217`.

## Effective resources and policy

Each host variant has its own reviewed `ACCESS.md` under `skill-tree-v1`.
Entries derive from the actual effective Codex or Claude body, including its
frontmatter, manual invocation, advertised tools, model preferences and capability
limits. They replace installed sibling assumptions with prepared qualified
references. Original `SKILL.md`, supporting content, metadata and modes remain
unchanged. Common sources and OpenCode definitions gain no on-demand contract.
All other skill contracts and other Pack versions remain unchanged.

The initiating explicit host and immutable snapshot travel through every nested
request and delegate, together with the target directory, writable scratch/output
and prepared entry/resource locations. Missing retained content requires restoring
that revision. pstack TDD and Matty TDD retain their distinct policies and qualified
identities, without renaming native skills or changing live selections.

Required resource edges include conditional calls; preparation never executes the
branch. Descriptive comparisons and routing recommendations remain optional
qualified advice, resolved only if selected and compatible in the initiating
snapshot. They add no false blockers or cycles. Native `requires` retains its
existing installation semantics, including broader background dependencies.

Discovery exposes reviewed metadata and unverified prerequisites. Supporting
references remain separate files read only for the active branch. Retrieval runs
no workflows, setup, preference writes, runtime installation, external searches,
review agents or project changes. Subsequent execution retains all source-defined
approvals, model diversity, independent review, target access and tool checks.

The changed variant trees retain adapted provenance and upstream attribution.
The unchanged imported MIT notice points to a terminal Catalog-authored MIT notice,
replacing its self-reference so on-demand legal closure is acyclic. Every skill
still retains the upstream notice, with the adaptation notice in its legal closure.

## Acceptance

From a clean committed candidate and clean complete 4.5.0 baseline:

```sh
python3 -B scripts/probes/content-probes.py --scenario pstack-foundational \
  --pstack-baseline /path/to/pre-change-catalog > /tmp/pstack-foundational-evidence.json
```

The existing released-binary runner builds both complete catalogs through the
single central release declaration. Evidence records source commits, builder,
archive digests, bounded child commands and outcomes. HOME/config/data/cache and
project roots are disposable and owned; no fixture is published. Ordinary checks
and successful-main publication remain inert and keep existing authority.

All 76 roots are checked for effective host identity/version/snapshot, independent
reviewed required edges and full closure, complete source/supporting/legal bytes
and modes, usable relative references and unverified prerequisites with content
runtimes absent. Representative principle/arena/utility links are followed after
a digest-bound selection transition. Nested access retains the initiating snapshot;
new independent requests see baseline incompatibility, old paths stay usable,
and missing retained content fails explicitly.

Both qualified TDD identities are retrieved with active, modified pstack native
TDD, preserving distinct policies and the installed copy. Discovery keeps why's
supporting bodies out of its metadata. State observations prove setup remains
inert and target/native/configuration/immutable resources stay unchanged. Native
installation regression covers the complete scoped selection on Codex, Claude and
OpenCode, comparing every original byte/mode and native contract to the baseline.
Owned verification state is removed. Resource access does not establish model-driven
workflow success or runtime readiness.
