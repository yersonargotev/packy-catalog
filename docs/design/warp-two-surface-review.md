# Warp two-surface transition: initial review

The 29 Warp skills keep their existing logical identities and retained on-demand
procedures. Both `agents` and `claude` select the reviewed common tree; the
surface binding is a discovery convention, not evidence that a client provides
Warp, Oz, a model, tools, credentials, or authorization. Each native entry now
states the same operational prerequisites as its reviewed on-demand variant.
This does not provision those dependencies or erase the original approvals,
stopping rules, and user decisions. Complete upstream notices and adaptations
remain part of the closure. `merge-risk` credits were flattened into a string to
meet plugin metadata requirements while preserving the attribution and URL.

inter-skill invocation: there is no invented Agent Plugins syntax and no Claude
namespace to rewrite. Where a row is excluded, neither format has a reviewed
adaptation that resolves the stated issue. Explicit selection fails rather than
silently dropping that candidate. The descriptions below do not imply that an
external tool or a runtime role has been provisioned.

## Bounded evidence

Packy v0.2.32 (`9d8a03a0c0070f20736d6f6ab94d4f5c303243ba`) validated a
Warp-only candidate with 60 fitness rows, including the two surfaces and retained
legal/source closure. Candidate `get skill warp:pr-walkthrough` on each surface
prepared its `warp:brandalf` dependency with the same snapshot identity; no
content was executed. Default candidate exports on each surface contained all eight eligible skills,
their bundled references and both notices. Explicit Claude selection of the
ineligible `pr-walkthrough` failed. These isolated, unauthenticated candidates
are not a published complete catalog and do not prove client installation,
authorization, runtime execution, or model-backed usability.
